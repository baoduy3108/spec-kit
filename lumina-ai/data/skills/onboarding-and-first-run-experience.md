# Onboarding & First-Run Experience

Onboarding is the make-or-break window: a new user decides in minutes whether your product is worth their time. The goal isn't to *explain* the product — it's to get the user to their **first real success** (the "aha moment") as fast as possible, because value felt beats value described.

## Time-to-Value Is the Metric

Every step between signup and first success is a chance to lose the user. Ruthlessly shorten it:
- **Defer everything non-essential.** Don't demand profile fields, team invites, or config the user can't yet see the point of. Ask for it *when it's needed*, in context.
- **Prefill and default** aggressively; do work for the user (import, sample data, sensible starting state).
- **A prebuilt example or template** lets users experience the product working before they've built anything — often the fastest path to "I get it."

## Progressive Over Upfront

The classic mistake is front-loading setup and tutorials before the user has any context:
- **Progressive disclosure** — reveal features as they become relevant, not all at once (see progressive-disclosure).
- **Contextual hints** — a tooltip on the button *when the user reaches it* teaches better than a 6-slide tour up front that everyone clicks "Skip" on.
- **Learn by doing** — guide the user through performing the core action for real, not watching a video about it.

## Empty States That Teach

The first time a user sees a screen, it's empty — and that's a prime teaching moment. A blank list should show: what goes here, why it's valuable, and a **clear primary action** to fill it (with a sample or a one-click create). A good empty state turns confusion into the obvious next step (see loading-states and user-flows).

## Tours: Use Sparingly

Coach marks and product tours are tempting but usually skipped and forgotten. If used:
- Keep them **short** (2–3 steps max), **interactive** (do, don't watch), and **dismissible**.
- Tie each step to an action the user takes, not a passive callout.
- Never block the UI with a mandatory multi-step gauntlet.

## Reduce Friction & Reassure

- **Delay the signup wall** where possible — let users try before committing account creation ("try, then buy/sign up").
- Show **progress** ("Step 2 of 3") for necessary multi-step setup so it feels finite.
- **Celebrate the first win** — acknowledge the aha moment so the user feels momentum.
- Make it **safe to explore** — reversible actions, sample data they can't break.

## Measure & Iterate

Onboarding is tuned with data: define **activation** (the action correlated with retention), then measure how many new users reach it and where they drop. Fix the biggest drop-off first. Onboarding is never "done" — it's continuously shortened.

The best onboarding is often barely noticeable: the product is so clear, and the first success so fast, that the user is productive before they realize they were being onboarded.
